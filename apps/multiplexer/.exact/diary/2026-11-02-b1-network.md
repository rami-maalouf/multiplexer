### Rough
- The app's `target/` folder was a copy of the same app's `target/` from another checkout (a second git worktree, to keep incremental builds). `exact.mjs ios --sim <udid>` compiled in 26 s, then failed: `no matching rustc unit dep-info for unicode_ident; searched target directory <app>/target; rebuild the stale Cargo unit or use a private target directory`. Cargo itself took the copied units as fresh; Exact's dep-info check did not, because 1140 of the 1626 `.d` files name the other checkout's absolute path (found by reading `scripts/cargo-dep-info.mjs`). The message does not say which command rebuilds "the stale Cargo unit", nor that the folder was built at another path. Cost about 10 minutes, then a clean `target/` and a full first build. What would have helped: the message saying "this target/ was built at <other path>; delete it (or `cargo clean`)", or the check accepting a unit whose `.d` names the same relative path under another root.
- In a plain `list` whose rows (`link` > `row`) start with a 44-point round picture that holds a person's initials as `text`, UIKit's separator under each row starts at the initials' left edge, so the separators jump left and right from row to row ("MM", "IB" and "MN" start at different x). A row whose picture is an `image` has its separator at the name, as Messages does. The contract guide says to draw none of a list's separators, `contract vocab separator` answers nothing, and no doc says where a plain list's separator starts. I read `GroupedListIOS.swift` (`itemSeparatorHandler`, `lineStart`) and the kernel's `grouped_separator`: the rule "after a leading symbol, at the text" covers only a `symbol:` image. One try (`aria-hidden=true` on the initials) changed nothing. Cost about 15 minutes; left as it is. What would have helped: the separator starting at the first text after a leading picture of any kind (as UIKit's own cells do beside an image), or a documented way to say where it starts.
- A list row is a `link` whose content holds a small `image` with `aria-label="<brand>"` (a logo on the corner of a picture). On iOS, `tree --ax` reads the link as its texts joined ("MN <name> 5:20 PM <preview>"): the image's label is left out, where the web counts an image's label in its link's name. A second try, `role="img" aria-label=…` on the image's box with the image `aria-hidden`, read the same. No doc says which children a row's spoken label joins, and none shows a way to add a word to it without writing the whole label by hand. Cost about 10 minutes; left as it is (the image keeps its label). What would have helped: a labelled image counting in its link's spoken label, as on the web, or a doc line naming the rule and the way around it.
- `"clock until state roomList.rooms.0 .network == \"whatsapp\" within 30000"` (the `expect state` form, with a space after the index) was refused with the grammar alone, though the app's own agent notes warn about it (a known finding). Cost: one drive, about 1 minute.
