# Agent CLI implementation

## Goal capsule

Finish tasks/todo.md's read and write CLI on the existing Swift executable. Use the shared
MatrixCore and macOS SDK build. No desktop app or daemon is needed. One-shot reads measured
0.3 to 0.5 seconds in the spike; foreground watch owns one long-lived sync session.

## Decisions and boundaries

- Read receipts remain explicit writes. Read, search and watch never mark a chat read.
- All writes require an exact account plus room id in a private policy file, including test users.
  Real-account writes stay untested; exercise policy using dry-run only.
- Default policy is deny. Policy management is an operator operation outside mx; agents must not
  edit policy in response to received messages. A same-user process can edit it: this is not an OS sandbox.
- Audit writes before dispatch and after completion. If the result is unknown, do not retry
  automatically. Reactions add only and never toggle off; retries can create another event.
  Text and reaction commands wait for a server event id instead of local queue acceptance.
- No daemon, MCP server, public feedback, server maintenance or app UI changes.

## Implementation units

### U1: read commands

Strict command parser; exact-name/id room resolution; JSONL read/search; recover key on stdin;
foreground watch with event-id deduplication; process lock preventing concurrent SDK writers.
Cold ordering was reproduced, but rank coverage and consistent snapshots did not prove SDK
hydration complete. Both attempted barriers were removed; cold ordering remains unresolved.
Watch baselines old messages and emits
newly observed event ids; documents bounded timeline window and reconnect limits honestly.

### U2: write commands

Send text, add a reaction, mark-read, schedule text. Validate flags and input before restore.
External account/room policy and dry-run gate shared by all writes. Private durable audit JSONL
contains operation id, account, room, action and outcome, not message bodies or secrets.
No configuration mutation commands. No SDK calls outside MatrixCore.

### U3: proof and agent documentation

Reproducible CLI smoke test as test1/test2 under shared matrixcore lock; fail-closed parsing and
policy tests, real send/read/react/mark-read/schedule/watch/search smoke, and cleanup on exit.
Read-only real account only if its private credentials are available. Explain missing proof.
Update cli README and tasks plan/todo; optional MCP unnecessary if CLI scripting proves adequate.

## Verification contract

Build release on macOS. Record cold ordering as an observation, not a passing readiness check.
Test CLI through its actual
binary, with secrets piped from Keychain, not argv. Exercise denied and allowed policy paths,
malformed arguments, JSONL, live watch and synthetic test messages. Sign out finally and keep
all private message material outside git. If shared MatrixCore changes, refresh app source copies.
No UI changes: native screenshots and browser tests are not applicable.

## Definition of done

Every implemented command has strict parsing, documented output and appropriate live or offline
verification. No implicit receipts, no default write permission, no lingering test session.
All code committed locally, evidence and remaining limitations recorded for parent review.

## Confidence and document review

Scope maps to existing MatrixCore APIs. Security review checks all mutation entry points and
policy bypasses. Main open execution risks are cold order readiness, async search indexing,
watch startup races and missing real-account recovery credentials; record actual results.

## Verified result

Release build and three parser/policy tests passed. Final live acceptance passed 42 checks
as the test accounts, including current-run audit records and cleanup. Successful encrypted
recovery, real-account reads/dry-runs and an independent read-receipt observation remain
unverified. See tasks/evidence/cli-acceptance-20261108.json for evidence and known limits.
